# 回归验证（Regression）

> 涉及已有能力的变更（接口/状态机/存储/渲染/性能/bug 修复）如何系统验证既有功能不被破坏。
> 本文回答「变更后重测什么」；维度名称与完成判定见 [verify.md](./verify.md) §2；观测手段见 [evidence.md](./evidence.md)。

## Use when

- 接口签名/状态机/存储层/渲染结构/性能任一变更后
- bug 修复后、发版前、跨层重构收尾
- 拿不准回归级别时（按 §2 取更高级）

## 1. 触发时机

| 触发场景 | 动作 | 违反后果 |
|----------|------|----------|
| 接口/状态机/存储/渲染/性能变更 | 完整回归（§3 全维） | 既有功能静默回归 |
| bug 修复后 | 按变更面定级（§2） | 修复引入相邻回归 |
| 发版前 | 完整回归 + [release.md](./release.md) 核对 | 带病发版 |
| 跨层重构收尾 | 完整回归 | 依赖方向/状态流破坏漏检 |

## 2. 变更分类与回归级别

| 变更类型 | 判定 | 回归级别 |
|----------|------|----------|
| 接口签名（方法挂起化/参数返回值变化） | 调用方全链影响 | 完整回归 |
| 状态机/数据流（FSM/事件处理/数据源增删） | 状态流转跨组件 | 完整回归 |
| 存储层（表/DAO/迁移/缓存） | 数据兼容与迁移风险 | 完整回归 |
| 渲染结构（列表重组/滚动补偿/渲染管线） | 时间性现象 + 性能耦合 | 完整回归 |
| 性能优化 | 必须证明「前 → 后」不退步 | 完整回归（含基线对比） |
| 单文件小修（一个条件/索引/字符） | 影响面单点 | 快速回归 |
| 纯文档/文案/i18n | 无逻辑路径 | 免回归（仅静态检查） |

**拿不准取更高级**：多跑一轮回归的成本，远低于漏检后的修复成本。

## 3. 回归维度（verify.md 命名维度的回归视角）

| 回归项 | 内容 | 何时必须 | 通过标准 | 对应维度 |
|--------|------|----------|----------|----------|
| 崩溃扫描 | 构建输出 + 静态检查 + 崩溃缓冲区扫描 | 所有变更（完整回归强制） | 0 error / 0 崩溃 | 构建 |
| 单测回归 | 先受影响模块，再全量（强制重跑防跳过） | 所有变更 | 0 failures | 测试 |
| 功能走查 | 按能力域清单执行（§4） | UI/状态/存储/连接任一变更 | 清单预期全部通过 | 运行时 |
| 基线对比 | 帧率/日志量/内存/冷启动，改动前后同场景 | 性能优化/渲染变更/完整回归 | 退化不超 10%，否则解释或回滚 | 遥测 |
| 人工验收 | 时间性现象（闪烁/动画/跳动/流式节奏） | UI 触及时间性现象 | 用户反馈记录 | 人工 |

### 3.1 基线纪律

| 步骤 | 动作 | 违反后果 |
|------|------|----------|
| 改动前 | 同场景先采基线（分位值、日志行数/秒） | 无基线则「优化」无法证明不退步 |
| 改动后 | 同设备/同场景/同数据量复测 | 变量不可比，结论无效 |
| 对比 | 退化超过 10% 必须解释或回滚 | 性能回归带病上线 |

## 4. 能力域清单

回归按**能力域**而非文件组织——文件会变，能力相对稳定。

| 规则 | 说明 | 违反后果 |
|------|------|----------|
| 从用户旅程切分 8-12 域 | 启动/核心功能/辅助功能三段；每域一轮走查不超过 15 分钟 | 过粗跑不完、过细清单膨胀 |
| 每域四件套 | 验证点列表（★ 快速必测标）/操作路径/通过标准/证据落盘路径 | 无法确定测什么、不可复核 |
| 新能力合入同步登记 | 不得「代码先进、清单后补」 | 清单与代码脱节 |
| 漏检回写 | 回归漏检时把该验证点补进清单（清单是活的） | 同一漏检反复发生 |
| 季度复查 | 删废弃域、补演进新点 | 清单腐化 |

清单本体存于项目 docs/ability-domains.md（骨架与维护规则模板：[templates/ability-domains.md](../templates/ability-domains.md)；init.sh 已实例化）。

## 5. 问题处理流程

```
发现问题（复现 + 采集证据：日志/截图/步骤/环境）
  ├─ 阻塞性（功能不可用/数据丢失/崩溃/严重退化）
  │     → 根因修复 → 复验受影响项 → 完成
  └─ 非阻塞（体验瑕疵/边缘场景/优化项）
        → 登记待办（backlog 卡片）→ 继续回归
```

### 定性三问（发现异常先定性再处置）

| # | 问题 | 判断 |
|---|------|------|
| 1 | 回归还是预有？ | 改动前基线/旧版本上是否同样存在？预有 → 登记不阻塞本次 |
| 2 | 阻塞还是非阻塞？ | 主流程/数据正确性是否受影响？ |
| 3 | 设计还是 bug？ | 产品设计如此，还是实现偏差？ |

违反后果：跳过定性直接处置 → 把预有问题当回归修、把设计当 bug 改。

### 补丁三件事

无法根因修复时走 [bug.md](./bug.md) §6 补丁协议（唯一归宿）；本文不重复。

## 6. 快速 vs 完整回归对照

| 场景 | 构建 | 测试 | 运行时 | 遥测 | 人工 | 能力域范围 |
|------|------|------|--------|------|------|------------|
| 免回归（纯文档/i18n） | 静态检查 | — | — | — | — | — |
| 快速回归（单文件小修） | 是 | 受影响模块 | 星标必测点 | — | 触及时间性时 | 1-2 域 |
| 完整回归（接口/状态机/存储/渲染/性能） | 是 | 全量强制重跑 | 全清单 | 基线对比 | 是 | 全部能力域 |

## 7. 证据落盘与回归报告

- 路径：项目 docs/research/主题/；命名 RG-编号-描述.扩展名（如 RG-01-crash-buffer.log）
- 回归报告用 [research-report.md](../templates/research-report.md) Part B
- 证据与报告随变更同 commit；发版回归证据归档到 release 目录
