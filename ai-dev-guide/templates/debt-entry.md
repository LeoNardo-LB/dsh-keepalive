# 债务条目模板（Debt Entry）

> 技术债务登记簿的条目格式、严重度标准与状态流转。登记纪律见 [debt.md](../workflows/debt.md)。

## Use when

- 登记技术债（补丁联动/顺带发现/可接受债务）时
- 偿还更新状态时

## 条目字段

```markdown
#### TD-<N> · <标题> · <严重度：高/中/低>

| 字段 | 内容 |
|------|------|
| 引入背景 | <哪个 commit/决策/演进引入> |
| 为什么是债 | <触发条件 + 后果（何时会痛、多痛）> |
| 建议根治方案 | <最小可行根治 + 预估代价> |
| 登记日期 | <YYYY-MM-DD> |
| 来源 | <backlog #N / 修复过程 / 审查> |
| 状态 | <待处理 / 处理中 / 已消除 / 已接受> |
```

登记最少内容 = 标题 + 严重度 + 为什么是债 + 状态（其余后续补）；编号 TD-N 递增永不复用。

## 严重度标准

| 严重度 | 判定标准 |
|--------|---------|
| 高 | 已影响正确性/安全/发版，或随时引爆；尽快排期 |
| 中 | 影响可维护性/性能/扩展，近期改动会踩坑 |
| 低 | 代码异味/一致性，长期隐患，暂不影响 |

## 状态流转（唯一词表）

```
待处理 → 处理中 → 已消除（附修复 commit，message 含 TD-N）
待处理 → 已接受（必须写理由：收益低于成本/平台细节/未来再做 + 未来触发条件）
```

| # | 规则 |
|---|------|
| 1 | 已消除/已接受条目不删除，保留追溯 |
| 2 | 已接受必须写理由 + 触发条件 |
| 3 | 偿还后跑回归（[regression.md](../workflows/regression.md) §2 分级） |

## 分类分节

登记簿按分类分节：架构违规 / 测试缺口 / 性能 / 遗留反模式（定义见 [debt.md](../workflows/debt.md) §3）；跨主题问题归入影响最大的主题。
