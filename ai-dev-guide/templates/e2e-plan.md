# E2E 测试双文档模板（期望文档 + 实操文档）

> E2E 测试按双文档模式拆为「期望文档（测前写，规定测什么、期望什么）+ 实操文档（测中记，逐轮对比期望）」；本模板一份文件承载两部分，复制后拆成两个文件使用。

## Use when

- 设计 E2E 测试（写 Part A 期望文档）前
- 执行 E2E 测试（填 Part B 实操文档）中
- 双文档模式的分离理由与交叉印证方法见 [../workflows/verify.md](../workflows/verify.md) §5——本模板只给结构

## 模板本体

### 使用说明（复制后删除本段）

- 期望文档**稳定可复用**：一次写好，发版 / 回归反复套用，只在功能变化时更新
- 实操文档**逐轮追加**：每执行一轮追加一节，只记事实，不改写历史轮次
- 两文档**必须分离**：期望（测什么）与实操（测到什么）不得混在同一文件，否则无法区分「没测到」与「没达到预期」
- 拆分方式：Part A 存为 `<功能名>-e2e-plan.md`，Part B 存为 `<功能名>-e2e-runbook.md`

### Part A — <功能名> E2E 测试期望文档

> 被测对象：<SUT>（如：主对话界面全生命周期）· 关联 spec：<spec 文件名，spec 头部挂 backlog 编号，见 [./spec.md](./spec.md)> · 配套实操文档：`<功能名>-e2e-runbook.md` · 测试工具：<E2E 工具>（命令与安装见 [../stack/stack-profile.md](../stack/stack-profile.md)）

**A0. 编排评估**：每项验证点归入三类，核心断言优先 SCR：

| 类别 | 定义 | 示例 | 执行方式 |
|------|------|------|----------|
| DYN（动态 UI） | 需真实 UI 交互 + 时间推进 | 点击发送、等待气泡出现、观察转圈消失 | 模拟器 tap/input + 截图 + UI dump |
| STA（静态断言） | 一次采集即可核对、不随运行变化 | 代码检查、单测 | 命令行直接执行 |
| SCR（脚本可核对） | 纯脚本轮询 / 断言，无需 UI | 服务器 API、数据库直查、日志过滤 | 脚本 + 观测命令 |

编排规则：
- 核心断言**优先 SCR**（可重复、可机器核对）；**视觉断言用 DYN**（截图 + 视觉分析）
- 同一结论至少 **≥1 SCR + ≥1 DYN** 交叉印证（如「消息已发送」= 日志事件 + 截图可见气泡）
- 观测点与日志期望见 [../workflows/evidence.md](../workflows/evidence.md) §1 / §2

**A1. 阶段划分与用例**：

| 阶段 | 目标 |
|------|------|
| 阶段 0 环境准备 | 模拟器 / 服务器 / 数据基线就绪（SCR） |
| 阶段 1 核心正向流程 | 主功能全链路走通（DYN + SCR） |
| 阶段 2 状态联动 | 状态机 / 列表 / 持久化联动（SCR + DYN） |
| 阶段 3 退出重进 | 退出与重进后状态恢复（DYN） |
| 阶段 4 逆向 / 异常 | 失败、断网、中断（DYN + SCR） |
| 阶段 5 极端边界 | 并发、超长、特殊字符、空输入（DYN） |

每个用例按此结构填写：

> **<用例编号> <用例名>**
> - 前置条件：<PRECONDITION>
> - 操作步骤：<STEPS>
> - 时间点截图断言：`0s` 截图 → 期望 <EXPECT_0>；`<N>s` 后截图 → 期望 <EXPECT_N>；未达重试 ≤<RETRY> 次
> - 日志 / 数据期望：观测点 <OBSERVE_POINT> 应出现 <EXPECT_LOG>（见 [../workflows/evidence.md](../workflows/evidence.md) §2）

**A2. 优先级与执行顺序**：

| 优先级 | 用例 | 理由 |
|--------|------|------|
| P0（必测） | <P0 用例> | 核心链路 + 已知回归点 |
| P1（重要） | <P1 用例> | 状态联动与异常恢复 |
| P2（补充） | <P2 用例> | 边界与极端场景 |

**A3. 通过标准（汇总）**：一份 E2E「通过」= 满足：
1. P0 用例全部通过（每用例 ≥2 独立维度交叉验证，见 [../workflows/verify.md](../workflows/verify.md) §3）
2. P1 用例 ≥<P1 阈值>%（默认 80%）通过；未通过项登记到实操文档「未达成项」
3. 无崩溃日志
4. 实操文档记录完整：操作时间线 + 实际观察 + 对比期望 + 判定
5. 档位联动：小改走冒烟档、发版 / 跨层重构走全面档（[../workflows/verify.md](../workflows/verify.md) §5 E2E 分档）



> 实操记录写在配套的 <功能名>-e2e-runbook.md（另一文件）；两文档必须分离。
