# Bug 修复记录模板（Bug Record）

> 修复完成时随 commit 附上的记录骨架（或写入批次 journal）。三层分类 + 判定三问结论是必填项。

## Use when

- 修复完成、提交 commit 时

## 模板本体

```markdown
### #<编号> <一句话症状>
- 症状：<用户/测试看到什么，影响面>
- 复现：<最小复现步骤>
- 根因：<机制级解释 + 引入点 commit/背景>
- 修复：<根因处改动描述>
- 验证：<原路径不复现的证据 + 回归范围（快速/完整）>
- 定性：<根治 / 补丁（三件事去向）>（附判定三问结论）
```

## 字段说明

| 字段 | 要求 |
|------|------|
| 症状 | 用户视角现象 + 影响面，不写内部对象 |
| 复现 | 最小步骤（他人照做可复现） |
| 根因 | 机制级解释；引用引入点（commit/决策背景） |
| 修复 | 描述「为什么这个改动让根因消失」 |
| 验证 | 证据 + 回归分级（[regression.md](../workflows/regression.md) §2） |
| 定性 | 根治/补丁 + 三问结论（上游下游/移除复发/新增复杂度） |

判定三问与补丁协议的**唯一归宿**：[bug.md](../workflows/bug.md) §4/§6（CANON 标记锁定）。
