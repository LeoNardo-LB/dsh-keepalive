# 发版说明模板（Release Notes Template）

> 每次发版（预发布与正式版）对外公告的撰写规范：面向用户的版本摘要 + 分类条目。
> 与 [./changelog.md](./changelog.md) 分工：Release Notes 每次发版都写、短；CHANGELOG 仅正式版更新、完整；分工细则见 [release.md](../workflows/release.md) 的 CHANGELOG 与 Release Notes 分工节。

## Use when

- 撰写 GitHub Release 说明 / 发版公告前
- 任何「本版改了什么」的对外说明前

## 标题格式

```
<项目名> <版本号> — <YYYY-MM-DD>
```

- 示例：`<项目名> 1.2.0 — 2026-08-06`
- 版本号与日期与本次发版一致；版本号规则见 [../workflows/release.md](../workflows/release.md)

## 模板本体

复制以下结构，**空分类整节删除**：

````markdown
## <项目名> <版本号> — <YYYY-MM-DD>

> <版本摘要：本版主题 1-2 句，必填>

### Added
- <动词开头的新增特性：做什么 + 入口在哪>（PR #<编号> / <commit 短哈希>）

### Changed
- <改进/优化：旧行为 → 新行为>（PR #<编号>）

### Deprecated
- <已弃用功能的预告与替代方案>（PR #<编号>）

### Removed
- <已移除功能；破坏性变更前置 **BREAKING:**>（PR #<编号>）

### Fixed
- <修复：用户看到的问题 → 现在已解决>（PR #<编号>）

### Security
- <安全修复；涉及 CVE 附链接>（PR #<编号>）
````

## 写作规则

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | **面向用户**：用户视角描述变化；不粘贴 commit message，不写内部实现（重构 / CI / 依赖升级 / 测试一律跳过） | 用户看不懂，噪音稀释重点 |
| 2 | **每条动词开头**：新增用「新增」，修复用「修复」，改进用「优化」 | 名词开头 → 条目像清单而非变化 |
| 3 | **每条附 PR / commit 引用**：正文后括号写 `PR #<编号>` 或 `<commit 短哈希>` | 无法追溯到变更来源 |
| 4 | 版本摘要必填：1-2 句概括本版主题 | 缺摘要 → 读者不知本版核心 |
| 5 | 新增特性写「做什么 + 入口在哪」 | 只写做了什么 → 用户找不到功能位置 |
| 6 | 修复写「用户看到的问题 → 现在已解决」 | 只写内部修复对象 → 用户不知影响 |
| 7 | 破坏性变更置顶醒目：`**BREAKING:**` 前缀 + 迁移/影响说明 | 破坏性变更被淹没 → 用户升级踩坑 |
| 8 | 空节省略：只保留有内容的分类 | 空分类占位 → 扫读噪音 |
| 9 | 范围：只写本版本（last tag → HEAD）相对上个版本的变化 | 重复历史 → 篇幅膨胀、重点丢失 |
| 10 | 每条 1-3 句，加粗关键名词便于扫读 | 长条目 → 扫读失败 |

## 分类条目示例

| 分类 | 正例 | 反例 |
|------|------|------|
| Added | 会话列表新增**未读红点**：进入会话自动消费（PR #123） | 新增未读红点功能（无入口） |
| Changed | 文件查看器加载动画统一为跳动点风格（PR #125） | 重构列表状态切片（内部实现） |
| Fixed | 修复**杀进程后未读红点丢失**：重启后仍能恢复（PR #124） | 修复红点持久化 bug（内部细节） |
| Removed | **BREAKING:** 移除自更新功能，升级需手动安装新包（PR #126） | 删除自更新模块（无用户影响说明） |

## 预发布与正式版差异

| 项 | 预发布（dev.n / beta） | 正式版（stable） |
|----|----------------------|------------------|
| 撰写 | 每次预发布都写 | 每次正式版都写 |
| 范围 | last tag → HEAD（只列上一 tag 之后的新变化） | 同上 |
| 摘要 | 标注预发布相位（Dev 预览 / Beta 预览） | 面向全体用户 |
| 篇幅 | 更短更聚焦 | 通常更长（含累积的预发布变更） |
| CHANGELOG | 不更新（仅正式版更新，见 [./changelog.md](./changelog.md)） | 正式版发布时同步更新 |

## 草稿生成与润色

| 步骤 | 动作 | 责任方 |
|------|------|--------|
| 1 | 发版脚本基于 last tag → HEAD 的 commits 自动生成草稿并粗分类 | 脚本 |
| 2 | 按「写作规则」润色：填版本摘要、改用户视角、删内部噪音、补 PR/commit 引用 | 发布者 |
| 3 | 草稿随发版 commit 提交，发布时作为 Release 说明 | 发布者 / CI |

## 发布前检查

| # | 检查项 | 违反后果 |
|---|--------|----------|
| 1 | 标题格式、版本号、日期与本次发版一致 | 版本错位 → 用户/CI 解析失败 |
| 2 | 版本摘要非空 | 缺摘要 → 读者不知本版核心 |
| 3 | 无内部实现条目（重构 / CI / 依赖升级 / 测试） | 内部噪音 → 用户扫读失败 |
| 4 | 每条均附 PR / commit 引用 | 无法追溯变更来源 |
| 5 | 破坏性变更已用 `**BREAKING:**` 置顶 | 用户升级踩坑 |
