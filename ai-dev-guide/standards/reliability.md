# 可靠性（Reliability）

> 让代码在异常输入、并发、资源压力与跨平台边界下**不崩溃、不丢数据、可诊断**的工程规范。

## Use when

- 编写涉及错误处理、重试、幂等、并发的代码时
- 处理跨平台边界（路径/编码/时区/换行）时
- 新增日志埋点、排查泄漏时

## 1. 错误处理分层

| 类别 | 定义 | 处理方式 | 例子 |
|------|------|----------|------|
| 可恢复 | 重试/降级/换路径后能继续 | 就地处理 + 日志 | 网络超时 → 退避重试 |
| 不可恢复 | 重试无意义 | 快速失败 + 明确错误态 + 上报 | 配置缺失 → 启动失败 |
| 需人工 | 状态不确定 | 保留现场 + 引导用户 | 数据损坏 → 隔离并提示 |

| 规则 | 违反后果 |
|------|----------|
| 异常必须被处理或显式传播，禁止空 catch 吞掉 | bug 被掩盖、现场丢失 |
| 捕获范围按错误类别收窄，禁止 catch 基类一把梭（把「锁竞争/磁盘满」误当「数据损坏」处理会误删全库） | 灾难性误操作 |
| 异步/后台任务必须有异常兜底，异常不得逃逸到框架边界 | 崩溃/任务卡死 |
| 错误消息含上下文（哪个实体、什么操作、原始错误链） | 无法定位 |

## 2. 输入与边界

| 规则 | 违反后果 |
|------|----------|
| 信任边界校验：外部输入（网络/用户/文件）进领域前校验，领域内部假设已校验 | 脏数据污染全链路 |
| 跨平台边界统一工具：路径分隔符/编码/换行/时区只在工具函数内处理，业务代码不感知平台差异 | 平台相关崩溃 |
| 时间一律带时钟域语义（服务器时间与本地时间分开，禁止混算） | 跨时区误报类 bug |
| 空值/默认值显式建模：可空类型/默认值语义写清，不靠「应该不会是空」 | 空指针与静默错误 |

## 3. 并发与状态

| 规则 | 违反后果 |
|------|----------|
| 状态单一真相源：可变状态收敛到一个服务 + 纯函数状态机，禁止多处各存一份 | 状态互相覆盖、竞态 |
| 共享可变状态用并发安全容器或加锁，且锁粒度写清 | 数据竞争、脏读 |
| 事件处理幂等：重复事件（重试/重连回放）不得造成重复副作用 | 重复消息、重复写入 |
| 取消语义显式：协程/任务取消路径必须释放资源、不得在取消回调里做重活 | 泄漏、崩溃 |
| 竞态防护：先检查后操作的模式要原子化或按状态机转移 | 竞态 |

## 4. 资源管理

| 规则 | 违反后果 |
|------|----------|
| 资源获取即规划释放：连接/流/锁/作用域有明确 owner 与关闭路径 | 内存/连接泄漏 |
| 缓存与注册表有淘汰/清理机制（上限 + 按 key 清理） | 无界增长 |
| 长生命周期对象（Service/Registry）提供 dispose/clear 语义并在断开时调用 | 跨连接状态残留 |

## 5. 日志规范

| 规则 | 违反后果 |
|------|----------|
| 统一日志门面：新代码只走统一门面（承重规则，见 AGENTS.md 红线） | 日志散落、诊断页不可见 |
| 级别语义：e=错误（不可恢复）· w=警告（可恢复异常）· i=关键业务路径 · d=调试细节（发版不输出） | 噪音淹没关键日志 |
| 关键路径必埋点：状态转移、网络事件、持久化、异常都要有可观测输出（取证手段见 [evidence.md](../workflows/evidence.md)） | 无法取证 |
| 敏感数据脱敏：密码/令牌/个人信息不入日志 | 泄露事故 |
| 日志带上下文：会话 id、操作名、关键参数 | 无法关联排查 |

## 6. 幂等与重试

| 规则 | 违反后果 |
|------|----------|
| 非幂等操作（支付/发送）要幂等键或去重 | 重复副作用 |
| 重试用退避（指数 + 抖动），并设上限与最终失败态 | 雪崩/无限重试 |
| 事件/消息处理按 id 去重（断连重连会回放） | 重复处理 |

## 7. 防御性编程的分寸

| 该防 | 不该防 |
|------|--------|
| 信任边界（外部输入） | 领域内部已被校验的值 |
| 平台差异（路径/编码/时区） | 「万一哪天真出问题」的想象场景 |
| 已知历史事故点 | 不可能到达的分支（宁可用断言暴露） |

过度防御会稀释真正需要防御的点——防御与风险成正比。
