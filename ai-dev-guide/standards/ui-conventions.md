# UI 统一性（UI Conventions）

> UI 样式的单一真相源与统一性纪律：四大质量目标、框架忠诚、设计令牌、状态展示、无障碍与本地化。

## Use when

- 编写、修改或评审任何 UI 组件、样式、配色、间距、动效时
- 决定是否引入新 UI 依赖、或需要自定义绘制组件时
- 涉及任何用户可见文案时

## 1. 四大质量目标

| 目标 | 定义 | 判定标准 |
|------|------|----------|
| 统一 | 全应用一套视觉语言：颜色/字体/形状/动效均出自同一令牌系统 | 任意两屏不出现「另一套」视觉风格 |
| 一致 | 同类场景用同一组件、同一行为 | 列表项/对话框/空态/错误态/加载态各只有一个实现 |
| 简洁 | 信息密度适当 + 渐进披露 | 每屏只有一个主行动，次要信息可折叠 |
| 可靠 | 不闪烁、不跳动、不丢状态 | 交互全程无可见抖动，配置变更后状态不丢 |

## 2. 框架忠诚原则

优先使用框架原生组件、原生样式与原生配色；只有原生能力无法满足时才逐级降级。

| 层级 | 适用条件 | 要求 |
|------|----------|------|
| 1 框架扩展机制 | 基于原生组件的扩展 API 可满足 | 直接用扩展，不新增依赖 |
| 2 自绘组件 | 扩展机制也无法满足 | 注释说明原因 + 补齐可访问性（§6） |
| 3 第三方库 | 自绘成本超过库的长期维护税 | 先评审（许可/体积/维护活跃度/兼容性）并记录 |

自定义设计四步法（降级到自绘/引库后必走）：

| 步骤 | 内容 | 违反后果 |
|------|------|----------|
| 1 证明缺失 | 引用官方文档证据确认原生无法表达 | 重复造轮子 |
| 2 令牌化 | 新视觉值进入令牌系统（§3） | 魔法值扩散 |
| 3 单点实现 | 唯一实现处，组件名可检索 | 多实现并存 |
| 4 登记 | 在本文档记录；临时方案登记技术债 | 决策不可追溯 |

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 禁止随意引入额外 UI 依赖库——每个都是长期维护税 | 依赖膨胀、升级阻塞 |
| 2 | 引入第三方 UI 库必须评审并记录理由，禁止顺手加上 | 决策不可追溯 |

## 3. 设计令牌系统

令牌是 UI 样式的唯一真相源：颜色、间距、形状、动效、排版、组件样式一律引用令牌，禁止散落魔法值。

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 语义透明度使用专用 Alpha 令牌，禁止裸值透明度 | 不可检索、暗色下对比度失控 |
| 2 | 新增令牌前先查现有令牌；同语义不新建不同值 | 令牌膨胀、互相矛盾 |
| 3 | 暗色主题信任框架默认调色板，只覆盖品牌差异化 token | 维护成本翻倍 |
| 4 | 删除令牌时全局清理引用，禁止保留死令牌 | 死代码累积 |

## 4. 组件分层与状态展示

| 层级 | 职责 |
|------|------|
| 主题层 | 令牌、配色、形状、排版；禁止业务逻辑 |
| 共享组件层 | 跨屏复用基础组件；只依赖令牌与状态输入 |
| 屏幕组件层 | 单屏专属组件；组合共享组件与业务状态 |

组件首次被 2 个以上屏幕复用时上移到共享组件层；屏幕组件禁止散落样式值。

每个数据驱动的组件/页面必须四态齐全：

| 状态 | 必须呈现 | 禁止 |
|------|----------|------|
| 加载 | 明确加载指示，不阻塞导航 | 空白屏、无反馈等待 |
| 空 | 空态文案 + 引导操作 | 只显示空白区域 |
| 错误 | 错误信息 + 重试入口 | 静默失败、仅写日志 |
| 禁用 | 视觉降级 + 不可交互 | 可用态视觉相同却不可点击 |

确定无某态需求须注明理由；错误重试后恢复正常态必须可感知。

## 5. 简洁性与可靠性

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 每屏只有一个主行动，其余降级为次要操作 | 多按钮互相竞争 |
| 2 | 渐进披露：次要信息折叠，首屏只呈现核心 | 信息过载 |
| 3 | 文案动词开头、省略主语、不技术腔 | 行动意图不清 |
| 4 | 避免模式打断：能就地编辑不弹窗 | 打断操作流 |
| 5 | 时间性现象（闪烁/动画/布局跳动/计时）自动化无法覆盖，必须列入人工验证清单（[verify.md](../workflows/verify.md) §8） | 时间性缺陷带病发版 |
| 6 | 需在配置变更/进程恢复后保留的状态用框架状态保存机制 | 状态丢失 |
| 7 | 流式/高频更新批量刷新而非逐条重组；流式文本用保持状态的解析器 | 振荡、闪烁、卡顿 |
| 8 | 动效可关：尊重系统「减少动效」设置 | 眩晕用户无法使用 |

## 6. 无障碍与触摸目标

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 触摸/点击目标最小尺寸达标（按平台规范，如 48×48 逻辑单位） | 难以点击 |
| 2 | 图标按钮与自绘组件必须提供语义描述 | 屏幕阅读器读不出内容 |
| 3 | 文本与背景对比度达标（普通文本 4.5:1、大文本 3:1） | 强光/视力障碍下不可读 |
| 4 | 自绘组件必须补齐焦点与语义，与原生组件等价 | 无障碍黑洞 |
| 5 | 动态文案与状态变化通过无障碍事件广播 | 用户感知不到更新 |

## 7. 本地化纪律

所有用户可见文案必须进入资源文件；文案改动是全语言事务，不是单文件修改。

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | 所有用户可见文案（含默认参数值）走资源加载 API，禁止代码硬编码 | 新增语言遗漏，或源语言用户看到外文 |
| 2 | 无翻译框架时用「源语言文件 + 翻译文件 + 检查脚本 + CI」模式 | 翻译不同步 |
| 3 | 源语言文件只含源语言文字 | 源语言界面出现外文 |
| 4 | 占位符（如 %1$s/%d）全语言与源文件完全一致 | 运行时崩溃、数字错位 |
| 5 | 同文案复用既有 key，不新建重复 key | key 膨胀 |
| 6 | 删除文案时同步清理全部语言文件，孤儿 key 一并删除 | 翻译文件膨胀 |
| 7 | 既有翻译为术语基准：新文案沿用既有译名 | 同一概念多种译法 |
| 8 | 数量词（plurals）新增时所有语言文件同步补齐 | 非默认语言回退或崩溃 |
| 9 | 检查脚本固定校验三项（key 完整性/源语言纯净性/占位符一致性） | 翻译回归无拦截 |

## 8. 发布前自检清单

| # | 检查项 | 依据 |
|---|--------|------|
| 1 | 无新增第三方 UI 依赖；若有则评审记录齐全 | §2 |
| 2 | 颜色/间距/形状/动效/排版/组件全部走令牌，无魔法值 | §3 |
| 3 | 新组件按分层目录放置，跨屏组件已上移 | §4 |
| 4 | 新增数据组件四态齐全；交互反馈完整 | §4 |
| 5 | 每屏一个主行动；文案动词开头 | §5 |
| 6 | 需恢复状态用框架机制；流式批量刷新；动效可关 | §5 |
| 7 | 触摸目标/语义描述/对比度达标 | §6 |
| 8 | 用户可见文案全部在资源文件，翻译同步，检查脚本通过 | §7 |
| 9 | 时间性现象已列入人工验证清单 | [verify.md](../workflows/verify.md) §8 |
